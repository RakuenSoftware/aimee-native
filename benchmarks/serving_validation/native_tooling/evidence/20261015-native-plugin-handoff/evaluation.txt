PRIVATE RESEARCH — Native LLM plugin handoff, 2026-10-15

The completion-boundary architecture now has a working private prototype and a
fresh stock Gemma4 E2B CPU run. The plugin holds completed contributions, sends
them to an owner over a private UNIX socket, accepts the owner's next resolved
publication and starts the next native inference segment. No tool-specific model
training, model parameter updates, GPU execution or public Git operations occurred.

Observed results

1. Typed proposal: E2B generated 15 from the native task publication. The real
   core scalar interpreter/compiler produced a privately bound write proposal.
   The fixture owner checked the odd 10..20 requirement, wrote the exact value
   and verified the observed file. The owner returned complete.

2. Native need/evidence loop: E2B initially assessed a synthetic link as likely
   able to sustain70MB/s, but also requested measured useful throughput. The real
   core semantic interpreter selected lookup-0; its compiler bound a fixture
   read_file. The owner read52MB/s and distributed the next native publication.
   Revision999 ->001 was accepted as supplied, without revision ordering.

   On the resumed inference segment E2B explicitly revised its assessment to
   'not currently sustaining the requested throughput of70MB/s', citing52MB/s.
   It also asked for the installation date. The owner interpreter selected that
   second need, but this fixture's preconfigured two-contribution budget ended
   the episode with clarify. The second lookup was not executed. This is a
   demonstrated native evidence loop, not a completed autonomous report task.

3. Eleven local tests pass: binding to request/session; stale ordinal/digest
   rejection; nonterminal output exclusion; opaque revision distribution;
   bounded contributions; serialization; real UNIX framing; deadline handling;
   cancellation; double cancellation; failure to confirm cleanup blocks reuse.
   These are protocol/lifecycle tests, not eleven model capability trials.

4. Both owner sessions closed. At each cleanup, active requests and worker pins
   were zero. Both owned systemd units ended inactive with Result=success and
   ExecMainStatus=0. The actual source and fixture effect bytes were independently
   checked against the collected remote archive. Prior sealed evidence is intact.

Costs and scope

Three task-model calls:84 ordinary input tokens and512 output tokens. Native
publication preparations used74,104 and122 prefix tokens; bank sizes were
6,365,184 /8,945,664 /10,493,952 bytes. Two owner semantic calls separately used
684+539 input tokens and86+66 output tokens. Preparation inference and other
runtime costs are not included in the84-token ordinary task input total. There
is no overall context, compute or latency reduction claim.

The owner service is explicitly a synthetic identity/resource fixture using the
existing real core resolver binaries. Full live enrollment, source/memory guards,
durable effect replay and the physical canonical dispatcher were not exercised
through this new serving loop. The fixture owner alone maps tools/resources and
executes effects; the plugin does not choose or authorize those operations.

Implementation is a new local plugin-package orchestration component, plus this
private driver. The driver invokes the component against real CPU native vLLM
serving. It is not yet wired into ordinary serving as an automatic interception
layer. This test uses one serialized global publication lane; multi-user serving
needs the existing per-request selection/pin path integrated and qualified.

The chosen handoff uses internal completed text contributions. It does not claim
a semantic intent detector reading intermediate tensors, nor an in-place pause
and continuation of one decoder sequence. Updated state is supplied natively to
a new inference segment. Aimee owns what information and evidence it distributes.

Direction

This gives us a concrete base: implement the native plugin as the host of the
inference/owner loop, using completion boundaries first. Keep semantic resolution,
capability bindings, source authority, revision distribution and effects in Aimee.
The next integration is the enrolled owner channel and serving entrypoint, with
request-bound native selection replacing the fixture's single publication lane.
Deliberate yields and intermediate signals remain optional later investigations.

A shorter native-instruction variant was prepared but not run: the original
scenario already demonstrated the requested lookup and native refresh. Its source
is retained as unexecuted material, not experimental evidence.

Artifacts are private under this directory. No commits, pushes, PRs, merges,
releases, external messages or Aimee production changes were performed.

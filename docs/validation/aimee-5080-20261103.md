# RTX 5080 validation with Aimee v1.0.2

This supplements the [.252 CPU and released-application audit](aimee-v1.0.2-20261103.md)
with actual CUDA execution on `.253`. It uses the same rebuilt, unpublished
`0.3.4.dev0` wheel bytes. Historical package/experiment evidence remains unchanged.

All five installed plugins pass their recorded lifecycle profiles: **65 checks**
against real Aimee v1.0.2, plus **94 source bridge tests with no skips** and
**28 released-application checks**. The [decision](artifacts/aimee-5080-20261103/decision.json)
identifies each accepted report; the [manifest](artifacts/aimee-5080-20261103/manifest.json)
hashes retained evidence and validation tools. These are unpublished, unsigned
candidate artifacts with the qualification boundary below.

## Environment and isolation

A fresh CPython 3.12.16 environment installs vLLM 0.30.0, Torch
2.13.0+cu130, CUDA 13.0 and Triton 3.7.1. The upstream dependency resolution
includes Transformers 5.22.1 and GGUF 0.19.0. Exact
[dependency versions](artifacts/aimee-5080-20261103/environment.json) and
[hardware/wheel hashes](artifacts/aimee-5080-20261103/hardware-and-artifacts.json)
are retained. The RTX 5080 has 16,303 MiB VRAM and driver 615.71.09.

The existing Wolf service remains running. Other encoder processes appeared during validation, one reaching
approximately 3.6 GiB device residency. They were left untouched; their lifetimes
were independent of this gate. The initial model profiles request 60% GPU utilization and 512 KV blocks.
CPU offload is explicit and model-specific; a requested budget does not
establish that a checkpoint or its loader supports offloading. No existing service, environment or
production account is adopted. The test environment and caches are disposable.

## Source and installed GPU operations

The [complete source bridge gate](artifacts/aimee-5080-20261103/bridge-gpu.json)
passes **94 tests, zero skips, zero exclusions**. This includes the upstream
vLLM authentication middleware, actual ChatCompletionRequest schema, GGUF loader,
hybrid worker gate and real CUDA attention comparisons. The attention test covers
18 combinations of widths 64/256/512, global/local windows and soft caps, with
ragged requests, scrambled paged text and independent native memory banks.

The portable numerical gate passes for the development library and every
installed, compiled dedicated namespace:

Each run checks six bit-exact BF16 decoder lengths (1, 17, 255, 256, 257,
65,536), including escapes and partial blocks, plus five attention comparisons
against an independent PyTorch calculation. All compiled model namespaces invoke
the common compiled kernel module and their own portable Rust library.
[Installed ABI, ownership, namespace, license and command checks](artifacts/aimee-5080-20261103/installed-models.json)
also pass **51/51** in this CUDA environment; their position checks remain CPU checks.

These numerical results do not by themselves establish pretrained model recall,
source authorization, model quality, streaming, concurrency or multi-GPU support.
Reproduction commands and the optional real-model gate are documented in
[development](../development.md).

## Reproduction and corrected setup assumptions

The disposable server uses the shipped v1.0.2 Compose/Vault helpers at
`204d4e55828993a7683cb2610fb4165e44cabb9f`, verified with a clean source checkout.
The guest has standard Docker 26.1.5 and Compose 2.26.1. It inherits an unlimited
memory-lock ceiling for the release's requested container limits. It supplies a
working C compiler and CUDA driver discovery to Triton; a host-only CUDA probe
is insufficient to qualify a fresh guest.

The [setup-attempt receipt](artifacts/aimee-5080-20261103/setup-attempts.json)
separately records failed/interrupted preparation runs. Initial mistakes included
missing upstream/helper dependencies, the guest's memory-lock ceiling, long Unix
socket paths, its absent C compiler and too few KV blocks for 2,048-token serving.
The gate now uses short private paths, real checkpoint hashing and the loaded
model's private `paused` control status. Withdrawn HTTP health is intentionally
503 and must not be used as a prerequisite for the first authorized request.
The hybrid system-turn rejection check applies to Qwen's complete prefix;
Gemma's attention-only path has a different request contract.

All GGUF checksums are calculated from actual tested bytes. The recovered NAS
small-model files differ from the older converted Q8 fixtures despite similar
historical path names. Their tested identities and mixed quantization are bound
separately; old result hashes are never edited to fit the recovered files.
The [profile inputs](artifacts/aimee-5080-20261103/profiles.json),
[model/tokenizer identities](artifacts/aimee-5080-20261103/model-identities.json)
and [complete Qwen FP8 checkpoint manifest](artifacts/aimee-5080-20261103/qwen-fp8-checkpoint.json)
identify the selected checkpoints. Temporary absolute paths in these inputs
identify this run and must be replaced with local paths for reproduction.

## Actual released-server model execution

The [initial installed-model run](artifacts/aimee-5080-20261103/serving-initial.json)
passes **13/13 lifecycle checks each** for Gemma 12B Q4_K_M, E2B UD-Q4_K_XL
and E4B UD-Q4_K_XL. Each uses a normal enrolled identity issued by the real
Aimee v1.0.2 application, with synthetic personal memory only. The checks cover
checkpoint hashing, enrollment, loaded/withdrawn readiness, missing-key rejection,
cold/warm native recall, publication reuse, ordinary source correction and a new
publication, and ordinary retirement followed by `unknown` instead of the old value.

The initial combined run is explicitly **failed**, because Gemma 26B and Qwen
could not start with its profile settings. Its
[application wrapper result](artifacts/aimee-5080-20261103/release-initial.json)
records that verdict and successful stack teardown. The passing model rows do not
turn that wrapper into a pass. The [profile-correction receipt](artifacts/aimee-5080-20261103/profile-corrections.json)
records both failures: GGUF MoE CPU offload attempted to detach an uninitialized
parameter, and a fixed hybrid cache override attempted a 24.50 GiB GPU allocation.
Those settings are not qualified by this run.


The [corrected retry](artifacts/aimee-5080-20261103/serving-retry.json) passes
**13/13** for Gemma 26B Q3_K_M and **13/13** for Qwen FP8, including Qwen's
changed-system-context rejection. The [retry profile inputs](artifacts/aimee-5080-20261103/retry-profiles.json)
use 0.88 GPU utilization with zero CPU offload for Gemma 26B; Qwen uses 0.60,
automatic KV sizing, a 24 GiB CPU-offload request and a 512 MiB native-device
budget. These are distinct profiles, not interchangeable flags.

[Sampled Qwen startup observations](artifacts/aimee-5080-20261103/qwen-runtime-observations.json)
report 22.68 GiB CPU-offloaded parameters, 4.87 GiB model-loading memory and
3.69 GiB available KV memory with automatic sizing. These are startup diagnostics,
not isolated latency/throughput measurements or a concurrency qualification.

The [aggregate decision](artifacts/aimee-5080-20261103/decision.json) accepts
**65 lifecycle checks across all five installed plugins**, preserving the initial
negative profile results. The [final real-application wrapper](artifacts/aimee-5080-20261103/release-retry.json)
passes **28/28** checks, including actual server-side enrollment revocation and
subsequent Rust-client refusal, and confirms Compose teardown with volumes.

## Qualification boundary

This qualifies these exact unsigned `0.3.4.dev0` wheel hashes, the recorded
checkpoint/tokenizer/config identities and single RTX 5080 CUDA environment for
the stated synthetic personal-memory lifecycle. It does not certify Qwen Q4,
Gemma 12B UD-Q4_K_XL, other checkpoints, ROCm, streaming/concurrency,
multimodal inputs, multi-GPU serving, signed upgrade/rollback or production
organization-memory authorization for these rebuilt bytes. Historical results
keep their original scope and artifact identities. Release signing, distribution
review and publication gates remain in [public release preparation](../public-release.md).

The [cleanup receipt](artifacts/aimee-5080-20261103/cleanup.json) confirms removal
of the owned guest/root volume, all Compose resources, test environments/caches,
copied checkpoints, read-only snapshot mounts/loop devices and the temporary
Python link. Wolf remains under its original PID with the same 524 MiB residency.
No model weights, private enrollment material or private service logs are retained
in this repository.

# Aimee Native 0.3.4

The first AGPL release provides the qualified five-model wheel set through
[GitHub Releases](https://github.com/RakuenSoftware/aimee-native/releases/tag/v0.3.4).
Start with the [public downloader and installation guide](../../distribution/release/github/v0.3.4/INSTALL.md).
The earlier
[5080 validation](../validation/aimee-5080-20261103.md) qualifies the executable
payloads rebuilt as `0.3.4.dev0`; stable packaging adds dependency notices and
version metadata without replacing those payloads. Final installation evidence
records the exact stable wheel hashes. Delivery uses the same seven wheel bytes;
the complete pinned source is packaged as a reproducible ZIP. See the
[delivery record](0.3.4-delivery.json) and
[signed release manifest](../../distribution/release/github/v0.3.4/manifest.json).

Signed installation qualification now covers clean `0.3.4.dev0` installation,
upgrade to `0.3.4`, rollback to that same development candidate, and restoration
of `0.3.4`: 51 installed ABI/configuration/entry-point checks per step, 204 in
total, with `pip check` passing at each step. This does not establish upgrade
compatibility with arbitrary older production versions.

## Compatibility

The advertised profile is Linux x86-64, CPython 3.12, glibc 2.41 or newer,
vLLM 0.30.0, Torch 2.13.0 with CUDA 13.0, Triton 3.7.1, Transformers 5.22.1,
GGUF 0.19.0, one NVIDIA RTX 5080 and the exact model profiles in the linked
validation. The tested driver is 615.71.09. Install the compatible GPU runtime
in an isolated virtual environment first. The signed installer is offline and
does not resolve or replace that runtime.

On the qualified Linux/CUDA host, prepare the environment before the signed
installation step:

```sh
python3.12 -m venv /path/to/venv
/path/to/venv/bin/python -m pip install \
  'vllm==0.30.0' 'torch==2.13.0' 'transformers==5.22.1' \
  'triton==3.7.1' 'gguf==0.19.0'
/path/to/venv/bin/python -m pip check
```

The tested Torch wheel reports `2.13.0+cu130`; check `torch.version.cuda` is
`13.0` and that Torch can access the intended GPU before starting a model.
The driver and its CUDA library must be available inside any container.

All five model wheels are co-installable and require the matching shared
`aimee-native-runtime`. Gemma GGUF loading uses the included Apache-licensed
`vllm-gguf-plugin` 0.0.5+triton. Model weights are supplied separately. The
release does not advertise ROCm, streaming, concurrent requests, speculative
decoding, compilation or prefix caching. Application compatibility is Aimee
v1.0.2 with normal invitation/CSR/mTLS enrollment and current source checks.

## Verify, install and roll back

Obtain `release-bundle.py` and the public signing key through a separately
trusted copy of this repository. Do not trust a key solely because it arrived
inside the downloaded bundle. The SHA-256 fingerprint of the DER-encoded
2026 Ed25519 public key is:

```text
eba95c96cf22f1f2cc76606f851376dad401380fd3bdd54ecfb79d640c2f0eb5
```

Place all release assets in a dedicated directory, with no unrelated files.
The detached signature authenticates the exact manifest bytes. That manifest
authenticates every wheel, corresponding-source archive and notice document.

```sh
python3 distribution/release/release-bundle.py verify \
  --bundle /path/to/downloaded-assets \
  --public-key distribution/release/public-keys/2026-ed25519.pub \
  --expected-version 0.3.4
python3 distribution/release/release-bundle.py install \
  --bundle /path/to/downloaded-assets \
  --public-key distribution/release/public-keys/2026-ed25519.pub \
  --expected-version 0.3.4 --python /path/to/venv/bin/python
```

Stop the model before replacing installed wheels, then restart it using the
[operation guide](../usage.md). Signature/hash/version failures stop before pip
runs. A pip failure can leave a partial installation: stop serving, correct the
runtime problem and reinstall a complete verified bundle. This is not an atomic
deployment manager. Keep the previous verified bundle and the original model
configuration for rollback. Roll back with the same command, explicitly naming
that bundle's version; an unexpected version is refused. A valid signature does
not establish that a historical version is still secure or supported.

## Source and notices

AGPL-3.0-only applies to current project source. Release assets include exact
corresponding source, build scripts, Cargo locks and dependency notices. The
[dependency notice directory](../../distribution/release/notices) records
reachable Rust dependencies, Rust standard-library notices, Cython 3.3.1 terms
and the GGUF plugin license. The GGUF dependency's Python source also ships in
its wheel. External vLLM, Torch, CUDA and model distributions retain their own
terms; they are installed independently and are not bundled here.

The [data and archive notices](../../DATASETS.md) apply to the separate research
history. Original archived proprietary candidate metadata is preserved as
evidence and does not describe the new AGPL release wheels.

## Maintainer publication

The tag-triggered [release workflow](../../.github/workflows/release.yml) runs
CPU/packaging/documentation checks, reconstructs source from the immutable commit
in the manifest and verifies all signatures and hashes. Its repository-scoped
GitHub Actions token uploads a draft, downloads and verifies all assets, then
publishes. The operator signing key is not supplied to CI. A retry can complete
the same draft; mismatched targets/assets or incomplete published releases are
refused. Preserve automatic Codex reviews and the manifest's source revision.
The owner controls GitHub private vulnerability reporting and repository settings.

After publication, download all assets into a new directory without GitHub
credentials and run the verification command above with the independently
pinned key. Check documentation links and install into a fresh compatible
environment. Source preparation and local validation do not establish that a
public tag, assets or repository settings have actually been published.
